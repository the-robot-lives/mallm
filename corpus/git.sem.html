git — install and configure

Install the git version-control client, point it at the right package manager for your OS, set user identity, and wire the platform credential helper so HTTPS remotes stop asking for passwords.

Install with your OS package manager, set user.name and user.email globally, and pick the credential helper your OS ships (osxkeychain, libsecret, or Git Credential Manager). Git is a CLI with no daemon — nothing to start or enable. Install: brew install gitsudo apt-get install git or sudo dnf install gitwinget install Git.Git Identity: git config --global user.name "Your Name" and git config --global user.email "you@example.com" Verify: git --version prints git version 2.x.y

Below: per-OS install paths and PATH notes, config file locations and precedence, credential helper setup per OS, version-specific behavior guards, and an agent-facing verification runbook. Config precedence is always system, then global (--global), then local (--local, the repo's .git/config) — last write wins per scope.

 Install git per OS git install homebrew apt dnf winget scoop

Goal: get a current git binary from the platform package manager and confirm it is first on PATH.

Homebrew: brew install git. The binary lands at /opt/homebrew/bin/git on Apple Silicon (/usr/local/bin/git on Intel) and shadows the Command Line Tools git at /usr/bin/git because Homebrew is earlier on PATH. Keep the CLT installed — xcode-select --install — since some tooling shells out to it.

Debian/Ubuntu: sudo apt-get update && sudo apt-get install git. Fedora/RHEL: sudo dnf install git. The binary is /usr/bin/git on both families.

Winget: winget install Git.Git (Scoop alternative: scoop install git). Default install root is %ProgramFiles%\Git; git.exe is at %ProgramFiles%\Git\cmd\git.exe, and the installer puts that directory on PATH. Use Git Bash (%ProgramFiles%\Git\bin\bash.exe) for shell scripts; both shells run the same git.

Other platforms or pinned versions: build from source — make prefix=/usr/local all then sudo make prefix=/usr/local install after installing the tarball from kernel.org.

 Find the config files and set identity git config gitconfig identity precedence

Goal: know which file each git config scope edits on your OS and set the identity every commit carries.

Global config: ~/.gitconfig. System config for Homebrew git: $(brew --prefix)/etc/gitconfig; the Apple git under /Library/Developer/CommandLineTools keeps its own. Set identity with git config --global user.name "Your Name" and git config --global user.email "you@example.com".

Global config: ~/.gitconfig; system config: /etc/gitconfig. Same identity commands — git config --global user.name and --global user.email. Check effective values plus their origin with git config --list --show-origin.

Global config: %USERPROFILE%\.gitconfig (Git Bash sees the same file as ~/.gitconfig). System config: %ProgramFiles%\Git\etc\gitconfig. Identity commands are identical from PowerShell, cmd, or Git Bash.

 Wire the OS credential helper git credentials osxkeychain libsecret gcm https

Goal: make HTTPS remotes authenticate without prompting, using the helper your OS ships.

osxkeychain is built in: git config --global credential.helper osxkeychain. Tokens land in Keychain Access under the login keychain; remove a stale entry with git credential-osxkeychain erase on stdin.

Build libsecret from the git contrib tree (/usr/share/doc/git/contrib/credential/libsecret), then git config --global credential.helper /usr/local/bin/git-credential-libsecret. Quick fallback: credential.helper store — plaintext at ~/.git-credentials, fine for throwaway machines only.

Git for Windows bundles Git Credential Manager and enables it by default: git config --global credential.helper manager. It stores tokens in Windows Credential Manager and handles GitHub and Azure DevOps OAuth flows interactively.

Version-specific behavior

Dubious-ownership protection: working trees owned by another UID make git fail with fatal: detected dubious ownership. Trust the path explicitly with git config --global --add safe.directory /path/to/repo — common inside containers and WSL.

macOS 14 or newer: the Command Line Tools git is already 2.39+, so CLT-only machines are current enough for most workflows; install Homebrew git anyway to track the newest release.

Modern branch surgery is available: prefer git switch and git restore over the overloaded git checkout.

Set the initial branch name once and silence the hint on every git init: git config --global init.defaultBranch main.

Agent verification runbook

Verify a git install end to end git verify agent expected-output

Goal: prove the binary, identity config, and credential helper from a fresh shell with exact commands and expected output.

Run git --version. Expected stdout: git version 2.46.0 — any 2.x at or above the target baseline; exit 0. Run git config --global user.name && git config --global user.email. Expected: two non-empty lines, exit 0. Empty output with exit 1 means identity is unset — set both before any commit. Run git config --global credential.helper. Expected: osxkeychain on macOS, a libsecret path or store on Linux, manager on Windows. Exit 1 (no output) means HTTPS pushes will prompt. Run git init --temporary /tmp/mallm-git-check && git -C /tmp/mallm-git-check status --short. Expected: empty status, exit 0; then remove the directory.

Failure mode: command not found after install on macOS means PATH was read before Homebrew linked the binary — re-read PATH or open a new shell, do not reinstall.
